# 1장-1. 데이터 모델링의 이해

## 1. 모델링(Modeling)

> **모델링**이란 현실 세계의 정보를 컴퓨터가 이해하고 
> 처리할 수 있도록 구조화하는 과정이다.

현실 세계의 핵심적인 특징만을 선별하여
그림이나 도표 등 체계적인 형태로 표현한다.

- 목적에 부합하는 핵심 정보를 선별
- 정해진 표기법에 따라 단순화
- 대표적인 예시: **ERD(Entity Realationship Diagram)**

### 1.1 모델링의 3가지 특징

| 특징 | 설명 |
|---|---|
| **추상화** | 목적에 부합하는 핵심 정보만 선별하여 표현 |
| **단순화** | 복잡한 현실 세계를 간결하게 표현 |
| **명확화** | 해석의 모호함이 없도록 표현 |

### 1.2 모델링의 3가지 관점

| 관점 | 핵심 내용 |
|---|---|
| **데이터 관점** | 어떤 데이터가 존재하며 관계는 어떠한가? |
| **프로세스 관점** | 업무 데이터가 어떤 기능과 절차로 처리되는가? |
| **상관 관점** | 데이터와 프로세스가 서로 어떻게 영향을 주는가? |

---

## 2. 데이터 모델링의 3단계

| 단계 | 설명 |
|---|---|
| **개념적** | 업무를 이해하고 데이터의 핵심 골격을 설계 |
| **논리적** | 개념 모델을 바탕으로 논리적 구조를 상세히 설계 |
| **물리적** | 특정 DBMS에 실제 구현할 수 있도록 변환 |

**진행 순서**

1. 개념적 데이터 모델링
2. 논리적 데이터 모델링
3. 물리적 데이터 모델링

> **핵심:** 개념적 → 논리적 → 물리적 순서로
> 구체화된다.

## 3. ANSI-SPARC 3단계 스키마 구조

데이터베이스를 세 수준으로 나누어 정의함으로써 **데이터 독립성**을 확보하기 위한 구조이다.

### 3.1 스키마 종류

| 구분 | 관점 | 설명 |
|---|---|---|
| **외부 스키마** | 사용자·응용 프로그램 | 사용자별로 필요한 데이터만 보여주는 개별 뷰 |
| **개념 스키마** | 데이터베이스 전체 | 데이터베이스 전체의 통합된 논리적 구조를 정의 |
| **내부 스키마** | 물리적 저장 | 데이터가 실제로 저장되는 방식과 구조를 정의 |

**예시**

- 외부 스키마: 영업팀에는 고객·매출 정보를, 인사팀에는 직원·급여 정보를 제공
- 개념 스키마: 전체 데이터의 엔터티, 관계, 제약조건을 통합하여 정의
- 내부 스키마: 파일 배치, 저장 구조, 인덱스 등 물리적 저장 방식 정의

### 3.2 데이터 독립성

> **데이터 독립성**이란 어느 한 단계의 스키마가 변경되더라도 다른 단계와 응용 프로그램에 미치는 영향을 최소화하는 성질이다.

| 종류 | 변경되는 부분 | 영향을 최소화할 대상 | 예시 |
|---|---|---|---|
| **논리적 데이터 독립성** | 개념 스키마 | 외부 스키마 및 응용 프로그램 | 전체 데이터 구조를 일부 바꿔도 사용자 화면·프로그램은 가급적 그대로 유지 |
| **물리적 데이터 독립성** | 내부 스키마 | 개념 스키마 및 상위 응용 프로그램 | 인덱스나 저장 방식을 바꿔도 테이블의 논리적 구조는 그대로 유지 |

```text
외부 스키마 (사용자별 뷰)
       ↑
       │ 논리적 데이터 독립성
       ↓
개념 스키마 (DB 전체 논리 구조)
       ↑
       │ 물리적 데이터 독립성
       ↓
내부 스키마 (실제 저장 구조)
```

> **암기 포인트:** **논리적 = 개념 ↔ 외부**, **물리적 = 내부 ↔ 개념**. 완전한 무영향을 보장하는 것이 아니라 변경의 파급을 줄이는 것이 핵심이다.

## 4. ERD(Entity Relationship Diagram)

> 데이터 모델링의 결과를 **시각적으로 표현한 설계도**

엔터티와 엔터티 간 관계를 정해진 표기법으로 표현한다.

- 데이터 구조를 시각적으로 표현
- 사용자, 설계자, 개발자 간 의사소통 지원
- 대표적인 표기법: **IE 표기법**

### 4.1 ERD 작성 순서

1. 엔터티 도출
2. 엔터티 배치
3. 엔터티 간 관계 설정
4. 관계명 기술
5. 관계의 참여도 기술
6. 관계의 필수/선택 여부 기술

---

## 5. 핵심 암기 정리

- **모델링 특징:** 추상화, 단순화, 명확화
- **모델링 관점:** 데이터, 프로세스, 상관
- **모델링 단계:** 개념적 → 논리적 → 물리적
- **3단계 스키마:** 외부, 개념, 내부
- **ERD:** 엔터티와 관계를 시각적으로 표현
